# Программа: парк 3D-сетей (глобальная рамка)

> **Дата:** 2026-08-20
> **Директива юзера:** «подтянуть нейросети 3D которые только возможно, и раскрыть их потенциал».
> **Главный план поверх этого файла:** `roadmap.md` (фазы Ф0–Ф7). Здесь — инвентарь, гейт приёмки и условия возврата.
> **Связь:** `netsTexToolsPlan.md` (очередь треков), `postSideBackPlan.md` (фазы P1–P4), `techContext.md` (инфра).
> **Не отменяет:** правило «один трек за раз» и гейты. Это рамка, а не разрешение жечь GPU.

## Главный вывод инвентаря

Наш парк **одномерный**: все пять воркеров — это «картинка → форма или текстура». Продукт (AI_MESH) обещает **3D + текстуры + анимации**, и третий столб у нас пустой полностью. При этом добавление четвёртой img→3D сети даёт всё меньше: H0 это доказал эмпирически.

Поэтому «раскрыть потенциал» читаем как **расширение по классам возможностей**, а не по числу сетей.

## Правило приёмки новой сети (гейт, выведен из H0)

H0 стоил нам недели, потому что мы поверили обзорам и начали крутить ручки до проверки класса входа. Кодифицируем, чтобы не повторять.

1. **Родословная.** Чей это файнтюн и какого поколения? Hi3DGen = TRELLIS **v1**, а у нас уже v2 — обещание «круче Trellis» было про v1. Всегда смотреть, с чем сравнивается **бумага**, а не блог.
2. **Класс входа.** На чём сеть реально сильна (нормаль/фото/скан/мультивью) и совпадает ли это с нашим входом. Гладкий CGI-рендер и фото статуи — разные задачи.
3. **Есть ли рычаг качества.** Есть ли параметр разрешения/каскада, или потолок вшит в чекпойнт. Если вшит — тюнить нечего, вердикт сразу.
4. **Лицензия под EU prod.** `postSideBackPlan.md` P4.3: Hunyuan / Era3D / Zero123++ — **нет**. MIT / Apache-2.0 — да.
5. **Same-input A/B до любых ручек.** Один прогон на нашем эталоне (рыцарь / сундук) против T2-baseline. Если официальное демо на нашем же входе даёт то же — это контракт модели, закрываем.
6. **Два прогона same/worse → метод закрыт** (правило из `sideBackUnblock.md`).

Обзоры-рейтинги в источники **не** годятся: та же волна SEO-статей 2026 ставит Hi3DGen как «best geometry», что мы опровергли на своём входе за один джоб.

## Последовательный план (на основе `netParkResearch2026.md`)

Никого не сбрасываем со счетов: у каждой сети либо шаг, либо явное условие возврата. Порядок — по отношению «ценность / цена», один трек за раз.

### Шаг 1. N1 — T2 `1536_cascade` на bust-кропе

Уже стоит в очереди (`netsTexToolsPlan.md` § Очередь после H0). Один джоб, эндпоинт живой. Отвечает: добивается ли микро-рельеф на уже оплаченной сети, или нужна новая.

Исследование говорит, что шанс есть: абляция Direct3D-S2 показывает, что разница 256³ → 512³ → 1024³ — это именно про high-frequency детали. T2 на 1536 работает в верхней части этой шкалы.

**PASS** → микро закрыт своими силами, шаг 2 не нужен как срочный.
**FAIL** → идём в шаг 2 с ясной причиной, а не «попробуем ещё сеть».

### Шаг 2. Direct3D-S2 — главный новый кандидат на форму

Почему он, а не «ещё один Hi3DGen»: MIT, веса выложены, и у него есть **явный параметр `sdf_resolution=1024`** — тот самый рычаг разрешения, которого у Hi3DGen нет и который мы успешно использовали на T2.

| | |
|--|--|
| Веса | [`wushuang98/Direct3D-S2`](https://huggingface.co/wushuang98/Direct3D-S2), `direct3d-s2-v-1-1` |
| Код | [DreamTechAI/Direct3D-S2](https://github.com/DreamTechAI/Direct3D-S2), MIT |
| VRAM | 1024 ≈ 24 GB → 4090 проходит |
| Ops | по нашему ритуалу: `Dockerfile.direct3ds2` → CI → GHCR → свой volume → serverless `workersMin=0`. Не голый pod |
| Гейт | same-input A/B на рыцаре против T2 ultra **до** любых ручек. `sdf_resolution=1024` сразу (512 — промежуточный, README не советует) |
| Минус | текстур нет, как у Hi3DGen → PBR всё равно нашим путём |

### Шаг 3. TokenRig — новый столб продукта (анимации)

Самое ценное по «раскрыть потенциал», потому что это не +10% к остроте меша, а возможность, которой у нас нет вообще. Вход — **наш готовый T2-меш**, то есть T2 не трогаем и ничего не конкурирует.

| | |
|--|--|
| Код | [VAST-AI-Research/SkinTokens](https://github.com/VAST-AI-Research/SkinTokens), веса `VAST-AI/SkinTokens` |
| Что даёт | скелет + skinning weights, импортируемые в стандартный DCC-пайплайн |
| Числа | +98–133% к точности skinning и +17–22% к костям над SOTA (UniRig) |
| Первый прогон | рыцарь `armor_t2_v17_realistic.png.glb` → скелет → проверить в Blender/вьюере, что кости внутри меша и вес не рвёт палды |
| Резерв | UniRig, если у TokenRig окажется неполный релиз |
| Не брать сейчас | AniGen — он генерирует **свою** форму, это конкурент T2, отдельный разговор |

### Шаг 4. HoloPart — части и раздельные материалы

Разделить у рыцаря золото / ткань / кожу как **части**, а не маски в одном атласе. Побочно лечит «блик едет по всему мешу». Вход — тот же T2-меш.

### Шаг 5. Быстрый тир — и здесь возвращается Hi3DGen

Замер с форума: Hi3DGen ≈ **8.5 с** на голую геометрию против ≈ 167 с у TRELLIS.2. У нас он уже развёрнут, образ собран, volume оплачен — то есть быстрый тир можно получить **бесплатно по труду**, просто переставив уже готовый воркер на другую роль в продукте.

Альтернативы, если понадобится текстура в черновике: SF3D / TripoSR (MIT, секунды).

### Шаг 6. Условия возврата закрытых сетей

Не «закрыто навсегда», а «закрыто до конкретного события».

| Сеть | Вернём, если |
|------|--------------|
| **Hi3DGen как качество** | появится чекпойнт выше `trellis-normal-v0-1` (сейчас у Stable-X его нет) **или** зайдёт непроверенный класс входа: реальное фото / камень / плотная детализация при 1024 px |
| **Pixal3D как quality** | новый чекпойнт **не** на ElasticSLat/TRELLIS.2 **или** непроверенный класс входа (реальное фото). Не «ещё раз 1536 на A6000» — каскад уже получен, львы не стали скульптурой |
| **MVPainter W3b** | после шагов 1–2 текстура окажется узким местом, а не форма |
| **RVG** | появятся реальные 2–4 снимка (гейт не наш, а физический) |
| **TripoSG** | Direct3D-S2 провалит A/B — тогда берём вторую ставку из P4.1 |
| **Sparc3D / Ultra3D / Hitem3D** | выложат веса. Сейчас код закрыт, репо = реклама платного сервиса ([issue #25](https://github.com/lizhihao6/Sparc3D/issues/25)) |
| **Hunyuan3D** | сменят лицензию. Сейчас EU/UK/Korea прямо вне Territory, включая **Output** |
| **img2mv** | не вернём (класс FROZEN 2026-08-13) |

## Явно не делать

- Ширина парка — приоритет (директива юзера 2026-08-20, порядок в `roadmap.md` Ф2), но **набирается она сначала прогонами на официальных демо**, а не эндпоинтами: каждый свой эндпоинт = Dockerfile, volume и стоимость сопровождения. Сети с общим стеком селим в один образ (Pixal3D `main` ↔ наш T2-стек).
- Не верить рейтингам обзоров вместо same-input A/B. Две арены дают противоположные места для TRELLIS.2 (5-е и 17-е).
- Не брать Hunyuan / Era3D / Zero123++ (лицензия, EU вне Territory — цитата в `netParkResearch2026.md`).
- Не пытаться поднять Sparc3D / Ultra3D: весов нет, репо = реклама Hitem3D.
- Не крутить ручки Hi3DGen ради качества (четыре рычага отработаны). Переоткрытие — только по условию из шага 6.
- Не крутить Pixal3D (1024/1536 already worse T2). Переоткрытие — только по условию из шага 6.
- Класс img2mv не возвращаем (FROZEN 2026-08-13).
- Не ставить always-on: `workersMin=0`, pod terminate в той же сессии.
